# FCL 按键误触修复器

修 FCL（Fold Craft Launcher）游戏内虚拟按键「**点一次莫名触发多次**」的问题。

**不换安装包 · 免 root · 不注入进程 · 可一键还原。**

---

## 一、为什么这个仓库里没有「插件」

在动手前我先确认了 FCL 的插件机制能做什么、不能做什么（源码 `com.mio.plugin`）：

- `PluginManager` 扫描带 `fclPlugin` / `FCLNativePlugin` / `fclPlugin_V2` 声明的外部 App，取出的是 **nativeLibraryDir 与 meta-data**；
- `NativeLibPlugin` 把库路径和环境变量喂给**游戏进程**（JVM 侧）；
- 也就是说，插件是被 FCL 加载的一个独立 APK，**拿不到 FCL 自己的 Java 类和 View**，更没法改 `ControlButton` 的触摸逻辑。

再加上两个硬约束：没 root，改不了 `/data/app` 里的 APK；改了也过不了签名校验；Android 沙箱不允许一个 App 注入另一个 App 的进程。

**所以「做成插件注入进去」这条路，在没有 root 的华为手机上是行不通的。**

但有另一个入口被我找到了——FCL 的**控制器（按键布局）是放在公共目录的普通 JSON 文件**：

```java
// FCLPath.java
CONTROLLER_DIR = Environment.getExternalStorageDirectory() + "/FCL/control";
```

即 **`/sdcard/FCL/control/*.json`**。它不在 `Android/data` 私有区里，华为自带「文件管理」和任何拿到存储权限的 App 都能直接读写。

而"点一次变多次"里有相当一部分**根本不是代码 bug，是按键事件被重复配置**导致的——这部分改 JSON 就能根治。

---

## 二、根因（对着 FCL 源码说的）

以下行号对应 `FCL/src/main/java/com/tungsten/fcl/control/view/ControlButton.java`（main 分支）。

### 1. 一次点击 = 2 次输出（按下 + 点击重复）

`ACTION_DOWN` 立刻输出一次按下（456–468 行），`ACTION_UP` 时若时长 ≤100ms 再触发 `handleClickEvent`，又输出一次完整的按下+抬起（511–514 行）。

> 同一个按钮上**同时配了「按下」和「点击」**，一次物理点击就会触发两次。

### 2. 快速连点两下 = 3 次输出（点击 + 双击冲突）

`clickCount` 在 400ms 内累计到 2 就额外触发 `handleDoubleEvent`（515–527 行）。

> 同时配了「点击」和「双击」时，连点两下 = 点击 + 点击 + 双击。

### 3. 最凶的一个：「连续点击」开关开错地方

`handleAutoClick` 用 `postDelayed(..., 20)` 自我循环（730–751 行）。这个开关本意是配在「按下/长按」上做持续连发，一旦配在**「点击」或「双击」**上，一次触碰就启动一个 20ms 间隔的无限连发循环。

> 这是「点一下变成好几次」最常见的真凶。

### 4. 延迟感的来源

- 每次按下都 `setPressedStyle()` → `setBackground()` → 触发重绘，全在主线程排队；
- 指针跟随类按钮每收到一个 `MOVE` 就往主线程丢一次指针更新，快速滑动时堆积；
- 事件分发走 `Schedulers.androidUIThread()` 排队，队列一长就有肉眼可见的滞后。

清掉重复输出后，多余触发消失，体感延迟会明显改善。

### 5. 一个改不掉的：多指触摸缺陷

`onTouchEvent` 全程没有判断 `pointerId` / `getActionIndex()`。两根手指按同一按钮时，按下状态是布尔翻转（`handlePressEvent(!pressEvent)`）会来回错乱，抬起时可能漏发「抬起」信号 → 按键卡住、像延迟。

**这是代码缺陷，配置文件改不了**，只能等官方修，或自行编译改过的版本。

## 三、怎么用（华为手机）

1. **完全关闭 FCL**：多任务界面把它划掉。FCL 只在启动时读控制器，运行中改的文件会被它内存里的数据覆盖回去。
2. 打开 **文件管理 → 内部存储 → `FCL` → `control`**，里面的 `.json` 就是控制器（有多个就逐个处理）。
3. **备份**：长按复制一份，改名成 `原文件名.json.bak`，放同一目录。
   > `.bak` 结尾 FCL 不识别也不删除，是安全的还原点。
4. **下载本仓库的 `index.html`** 到手机（或电脑打开），用浏览器打开它。
5. 点「选择 .json 控制器文件」，选中刚才那个 `.json`。
6. 工具会列出所有问题项，默认已勾选推荐修复（严重 + 重复输出）。**「长按类」默认不勾**——连续挖矿/攻击常常是故意这么配的，请按自己的手感决定。
7. 点「生成修复后的文件」，得到同名 `.json`。
8. **覆盖回原位置，文件名必须和原来完全一样**。
   > ⚠️ FCL 启动时会删掉 `control` 目录里它不认识的文件名，改名保存会被清掉。
9. 重新打开 FCL，进游戏实测。

### 还原

把 `.bak` 改回原名覆盖回去，重启 FCL。原文件没被动过，随时可退。

---

## 四、注意

- 改完**必须重启 FCL** 才生效（`Controllers.getControllersFromDisk()` 只在启动时调用一次）。
- 本工具是**纯前端单文件**，在浏览器本地解析，**不联网、不上传任何数据**。
- 修改前先备份，改完先在单人世界试手感，再进存档。
- 若你的按键是**故意**配成「按下+点击」或「点击+双击」来实现某种操作，请不要勾选对应项——工具只做提示，勾不勾在你。

---

## 五、局限

第 5 条「多指触摸缺陷」和第 4 条「主线程排队延迟」属于 FCL 源码问题，本工具无法修复。要根治只能改 `ControlButton.java` 的触摸分发（补 `pointerId` 分支、把指针更新从 UI 线程队列里摘出来）后自行编译或向官方提 PR。
